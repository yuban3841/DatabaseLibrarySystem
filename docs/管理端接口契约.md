## 一、通用约定

| 项目 | 约定 |
|---|---|
| 基础前缀 | `/api/v1` |
| 协议 | JSON over HTTP(S) |
| 鉴权 | 请求头 `Authorization: Bearer <accessToken>` |
| 时间格式 | `YYYY-MM-DD HH:mm:ss`（Asia/Shanghai） |
| 字符集 | UTF-8 |
| 接口文档 | OpenAPI 3.0 + Swagger UI，暴露在 `3001/api-docs` |

**统一响应体**：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "page": { "page": 1, "pageSize": 10, "total": 57, "totalPages": 6 }
}
```

- `code < 400` 视为成功；`code >= 400` 时前端统一弹出 `message`。
- 列表接口才返回 `page`；非列表接口省略该字段。

**错误码约定**：

| code | 含义 | 前端行为 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数错误 / 必填缺失 | 展示 message |
| 401 | 未登录或令牌失效 | 清除本地令牌并跳转登录页 |
| 403 | 无权限 | 展示 403 页 |
| 404 | 资源不存在 | 展示 message |
| 409 | 业务冲突（名额已满、重复签到、状态不可变更） | 展示 message |
| 500 | 服务端错误 | 展示「服务器内部错误」 |

**分页请求参数**（所有列表接口）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 页码，从 1 开始 |
| `pageSize` | int | 10 | 每页条数，最大建议 100 |

**角色与权限码**：

| 角色 | 权限 |
|---|---|
| `ADMIN` | 全部 |
| `ORGANIZER` | 全部管理权限，但活动范围可限定为自己创建的 |
| `USER` | 无管理端权限（访问管理端接口一律 403） |

权限码：`activity:manage`、`registration:review`、`registration:export`、`checkin:manage`、`statistics:view`。
`/auth/me` 的响应体必须返回 `permissions` 数组，前端据此渲染菜单与路由。

## 二、认证 `/auth`（成员 C）

### `POST /auth/login`

请求：

```json
{ "username": "admin", "password": "admin123" }
```

- `username` 支持账号名或学号。
- 账号不存在与密码错误**返回同一条 message**（`账号或密码错误`），不要区分，避免账号枚举。
- 被禁用的账号返回 403。

响应：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbG...",
    "expiresIn": 7200,
    "refreshToken": "eyJhbG...",
    "user": {
      "userId": "U-00001",
      "studentId": "24050814",
      "name": "陈明轩",
      "college": "计算机学院",
      "role": "ADMIN",
      "status": "ACTIVE",
      "permissions": ["activity:manage", "registration:review"]
    }
  }
}
```

### `GET /auth/me` → `User`（同上 `user` 结构）
### `POST /auth/refresh` → `{ token, expiresIn }`
### `POST /auth/logout` → `{ code: 200 }`

## 三、活动 `/activities`（成员 C）

### `GET /activities`

管理端列表，**必须包含草稿与下架活动**（仅用户端列表才只返回已发布）。

| 参数 | 类型 | 说明 |
|---|---|---|
| `keyword` | string | 标题或地点模糊匹配 |
| `category` | string | 体育/文艺/学术/志愿/其他 |
| `status` | string | `DRAFT` / `PUBLISHED` / `OFFLINE` / `ARCHIVED` |

响应 `data`: `Activity[]`

```json
{
  "activityId": "ACT-1001",
  "title": "第12届校园马拉松",
  "description": "...",
  "cover": "https://...",
  "category": "体育",
  "capacity": 120,
  "enrolled": 48,
  "waiting": 0,
  "auditRequired": false,
  "startTime": "2026-09-25 08:00:00",
  "endTime": "2026-09-25 09:30:00",
  "registerDeadline": "2026-09-24 12:00:00",
  "location": "之江校区田径场",
  "latitude": 30.2001,
  "longitude": 120.0967,
  "status": "PUBLISHED",
  "creatorId": "U-00001",
  "creatorName": "陈明轩",
  "createdAt": "2026-09-13 10:00:00",
  "updatedAt": "2026-09-20 09:00:00"
}
```

> `enrolled` = 名额内已通过人数；`waiting` = 候补人数。
> **这两个字段请从报名记录聚合得出，不要单独维护，避免与报名数据脱节。**

### `POST /activities` → 新建，固定 `status = "DRAFT"`

请求体为去掉 `activityId/enrolled/waiting/status/creatorId/creatorName/createdAt/updatedAt` 后的 `Activity` 结构。
校验：标题必填且不重复；`capacity >= 1`；`endTime > startTime`；`registerDeadline <= startTime`。

### `GET /activities/{id}` → `Activity`

### `PUT /activities/{id}` → 更新（**按状态限制可改字段**）

| 当前状态 | 可改字段 |
|---|---|
| `DRAFT` / `OFFLINE` | 全部业务字段 |
| `PUBLISHED` | 仅 `title` / `description` / `cover` / `location` |
| `ARCHIVED` | 一律 409 |

改锁字段的请求返回 409，message 需列出被拒字段名（例：`已发布活动的 名额上限、活动时间 不可修改（下架后可改）`）。

### `POST /activities/{id}/publish` → `DRAFT`/`OFFLINE` → `PUBLISHED`
`ARCHIVED` 不可重新发布（409）。

### `POST /activities/{id}/offline` → `PUBLISHED` → `OFFLINE`
**下架仅停止新报名，已有报名与签到记录必须仍然有效。**

### `POST /activities/{id}/copy` → 生成新草稿
标题追加「（副本）」，**不复制报名与签到数据**，`enrolled`/`waiting` 归零。

### `DELETE /activities/{id}` → 逻辑删除
写入 `deletedAt`，**不做物理删除**；关联报名与签到记录保留。`ARCHIVED` 不允许删除。

### `GET /activity-categories` → `["体育","文艺","学术","志愿","其他"]`

## 四、报名 `/activities/{id}/registrations`（成员 C）

### `GET /activities/{id}/registrations`

| 参数 | 类型 | 说明 |
|---|---|---|
| `status` | string | `PENDING`/`APPROVED`/`WAITING`/`REJECTED`/`CANCELLED` |
| `keyword` | string | 学号或姓名模糊匹配 |
| `sort` | string | `createdAt`（默认）或 `waitingNo` |
| `order` | string | `ASC` / `DESC` |
| `page` / `pageSize` | int | 分页 |

响应 `data`: `Registration[]`

```json
{
  "registrationId": "REG-00012",
  "activityId": "ACT-1003",
  "userId": "U-01023",
  "studentId": "24056161",
  "name": "刘博文",
  "college": "机械工程学院",
  "status": "APPROVED",
  "waitingNo": null,
  "ticketCode": "TK-1003-U01023-0435",
  "rejectReason": null,
  "createdAt": "2026-09-19 10:22:31",
  "reviewedAt": "2026-09-19 15:04:12",
  "reviewerName": "陈明轩"
}
```

### `PATCH /registrations/{id}/review`

```json
{ "action": "APPROVE", "reason": "可选" }
```

| `action` | 规则 |
|---|---|
| `APPROVE` | 置为 `APPROVED`、清空 `waitingNo`、**生成 `ticketCode`**；名额已满返回 409；`REJECTED`/`CANCELLED` 不可再批准（409） |
| `REJECT` | 置为 `REJECTED`、**`reason` 必填**（缺失返回 400）、清空 `ticketCode`、**释放名额并自动把候补序号最小的一条转为通过** |

两条路径都必须写 `reviewedAt` 与 `reviewerName`，并落操作日志。

### `POST /registrations/batch-review`

```json
{ "registrationIds": ["REG-00012", "REG-00015"], "action": "APPROVE", "reason": "可选" }
```

响应 `data`: `{ "succeeded": 1, "skipped": 1 }`
**逐条处理**，单条冲突不影响其它条；跳过原因无需细分，但 `succeeded + skipped` 必须等于入参条数。

### `POST /registrations/{id}/promote` → 手动递补
仅 `WAITING` 可递补；名额已满返回 409；成功后置为 `APPROVED` 并生成 `ticketCode`。

### `GET /activities/{id}/registrations/export` → `application/octet-stream`
`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，
`Content-Disposition: attachment; filename=...`（文件名 URL 编码）。
列：学号、姓名、学院、状态、候补序号、报名时间、审核时间、审核人、电子票码、驳回理由。
使用 exceljs 生成。

## 五、签到（成员 D）

### `GET /activities/{id}/checkin-code`

```json
{
  "data": {
    "payload": "eyJhaWQiOiJBQ1QtMTAwMyIsImV4cCI6MTcxNjQwMDAwMDAwMH0=",
    "expiresInSeconds": 60,
    "checkinWindow": "2026-09-22 13:00:00 ~ 2026-09-22 15:00:00"
  }
}
```

`payload` 是二维码内容，**必须携带有效期并由服务端签名**（前端只负责渲染，不做校验）。

### `POST /checkins` → 扫码签到

```json
{ "activityId": "ACT-1003", "ticketCode": "TK-1003-U01023-0435", "latitude": 30.2, "longitude": 120.09 }
```

服务端校验顺序（任一失败即 409/404，message 需可展示给用户）：

1. `ticketCode` 必须存在且属于该活动 → 否则 404 `票码无效，未找到对应报名`
2. 报名状态必须为 `APPROVED` → 否则 409 `该报名未通过审核，不可签到`
3. 当前时间在活动开始前 30 分钟 ~ 结束后 30 分钟内 → 否则 409 `签到尚未开始` / `签到已结束`
4. 该报名未签过到 → 否则 409 `该同学已签到，请勿重复签到`

响应 `data`: `CheckinRecord`

```json
{
  "checkinId": "CHK-00101",
  "activityId": "ACT-1003",
  "registrationId": "REG-00012",
  "userId": "U-01023",
  "name": "刘博文",
  "studentId": "24056161",
  "method": "SCAN",
  "checkinTime": "2026-09-22 13:34:20",
  "operatorName": null
}
```

### `POST /checkins/manual` → 手动补签

```json
{ "activityId": "ACT-1003", "userId": "U-01023", "operatorName": "陈明轩", "remark": "可选" }
```

`operatorName` 必填（缺失 400）；目标必须是该活动的 `APPROVED` 报名（否则 409）；已签到返回 409。
`method` 记为 `MANUAL`，并落操作日志（记录操作人）。

### `GET /activities/{id}/checkins` → 分页 `CheckinRecord[]`（按 `checkinTime` 倒序）

### `GET /activities/{id}/checkin-board` → 实时看板（**前端每 5 秒轮询**）

```json
{
  "data": {
    "activityId": "ACT-1003",
    "activityTitle": "数据库原理工作坊",
    "capacity": 40,
    "approved": 40,
    "checkedIn": 27,
    "checkinRate": 68,
    "latest": [ "CheckinRecord（最新 10 条）" ]
  }
}
```

`checkinRate` = `round(checkedIn / approved * 100)`，`approved = 0` 时为 0。

## 六、统计（成员 D）

### `GET /statistics/dashboard`

```json
{
  "data": {
    "activityCount": 6,
    "publishedCount": 3,
    "totalRegistration": 274,
    "pendingReview": 6,
    "todayCheckin": 27,
    "avgCheckinRate": 68,
    "registrationTrend": [{ "date": "09-16", "count": 42 }],

    "hotActivities": [{ "activityId": "ACT-1003", "title": "数据库原理工作坊", "enrolled": 43, "capacity": 40 }]
  }
}
```

- `registrationTrend` 固定返回**近 7 天**（含今日），日期格式 `MM-DD`，缺日补 0。
- `avgCheckinRate` 为**已结束或进行中且已有人报名**的活动签到率均值，非算术平均全部活动。

### `GET /statistics/activity-comparison` → `ActivityComparisonRow[]`

```json
{
  "activityId": "ACT-1003",
  "title": "数据库原理工作坊",
  "category": "学术",
  "capacity": 40,
  "enrolled": 43,
  "approved": 40,
  "rejected": 0,
  "waiting": 3,
  "cancelled": 0,
  "checkedIn": 27,
  "checkinRate": 68,
  "startTime": "2026-09-22 13:00:00"
}
```

> **口径**：`enrolled` 为该活动**全部报名记录数**（含候补、驳回、取消）；
> `checkinRate` = `checkedIn / approved`。请按此口径实现，前端展示文案以此为准。
> 按 `startTime` 升序返回。

### `GET /statistics/export` → Excel（列同 activity-comparison）

## 七、后端必须守住的底线

这些是评审重点，也是本项目的验收标准，请 C/D 在实现时逐条核对：

1. **SQL 注入**：全部使用参数化查询 / 预处理语句（MySQL prepared statement），
   禁止字符串拼接 SQL。动态 `ORDER BY` 字段必须走白名单，禁止直接拼接用户输入。
2. **名额不超卖**：名额控制用**条件更新原子占位**，例如
   `UPDATE activity SET enrolled = enrolled + 1 WHERE activity_id = ? AND enrolled < capacity`
   并检查影响行数；不要「先 SELECT 再 UPDATE」两步式判断。
3. **唯一索引兜底**：
   - `registration` 表建 `(activity_id, user_id, status)` 相关唯一约束，防重复报名；
   - `checkin_record` 表建 `(activity_id, registration_id)` 唯一约束，防重复签到。
   并发场景下靠索引兜底，业务代码的查重只做友好提示。
4. **事务**：审核（批准/驳回 + 候补转正 + 计数更新）必须在同一事务内提交，
   任一步失败整体回滚，避免出现「名额释放了但候补没转正」的中间态。
5. **密码**：BCrypt（cost ≥ 12），禁止明文与 MD5/SHA1；登录接口做限流（如同 IP 5 次/分钟）。
6. **令牌**：access token 2 小时、refresh token 7 天（与项目计划一致）；登出需失效服务端会话。
7. **权限**：管理端接口逐个校验角色与权限码，不能只在前端隐藏菜单；
   ORGANIZER 访问他人活动需明确拦截。
8. **审计日志**：报名审核（通过/驳回/递补）、活动发布/下架/删除、手动补签均需落库，
   记录操作人、时间、目标 ID、前后状态；导出操作同样记录。
9. **归档**：活动自动归档由定时任务处理（node-cron），归档态不可修改与删除。
10. **时间**：全库统一 `Asia/Shanghai`，比较与窗口计算不要混用时区。
