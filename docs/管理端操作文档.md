## 一、环境准备与启动

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 |
| Node.js | 18.x 及以上（实测 v22.19.0 可用） |
| npm | 随 Node 附带即可 |
| npm 源 | `registry.npmmirror.com` |

```powershell
cd client
npm install          # 首次运行
npm run dev          # 启动开发服务器
```

浏览器打开 `http://localhost:5173`。

生产构建：

```powershell
npm run build        # 类型检查 + 构建，产物在 client/dist
npm run preview      # 本地预览构建产物
```

## 四、功能操作

### 4.1 首页概览 `/dashboard`

进入系统默认页。展示六项核心指标：活动总数、已发布、报名总数、待审核、今日签到、平均签到率；
下方为近 7 天报名趋势折线图、活动分类分布饼图、热门活动 Top 5（含报名进度条）。

用途：管理员每天登录先看这里，判断是否有堆积的待审核报名。

### 4.2 活动管理 `/activities`

**筛选**：支持按标题/地点关键词搜索、按分类筛选、按状态筛选，三者可叠加。

**列表列**：活动标题与状态标签、分类、名额进度（已批准/上限，满员红色提示并显示候补数）、报名截止、创建人、操作。

**各状态可执行操作**：

| 操作 | 草稿 | 已发布 | 已下架 | 已归档 |
|---|---|---|---|---|
| 编辑（全部字段） | ✅ | — | ✅ | — |
| 编辑（仅标题/描述/封面/地点） | — | ✅ | — | — |
| 发布 | ✅ | — | ✅ | — |
| 下架 | — | ✅ | — | — |
| 复制（生成草稿，不带报名） | ✅ | ✅ | ✅ | ✅ |
| 逻辑删除 | ✅ | ✅ | ✅ | — |
| 查看报名名单 / 进入签到 | ✅ | ✅ | ✅ | ✅ |

**新建活动**：点击右上角「新建活动」，填写标题、分类、名额上限、是否审核制、地点、
活动起止时间、报名截止时间、封面 URL、描述。新建后固定为**草稿**状态，
需要回到列表点「发布」才会出现在用户端。

**编辑约束**（前端提示 + 后端强制）：

- 草稿 / 下架：所有字段可改。
- 已发布：仅**标题、描述、封面、地点**可改；名额、分类、起止时间、报名截止被锁定，
  提交修改会被拒绝并提示具体哪些字段不可改。**要改这些字段必须先「下架」再编辑。**
- 已归档：完全不可修改。
- 报名截止时间不能晚于活动开始时间；结束时间必须晚于开始时间。

**下架 vs 删除的区别**（容易搞混）：

- **下架**：用户端不再展示、停止新报名；**已有报名与签到记录仍然有效**，可以照常签到。
- **逻辑删除**：从管理端列表移除，数据库不做物理删除，报名与签到记录保留。
- 两者都不可恢复，操作前有二次确认。

### 4.3 报名审核 `/registrations`

页面顶部先**选择活动**，然后按状态分页签查看名单：全部 / 待审核 / 已通过 / 候补 / 已驳回 / 已取消。

**筛选与排序**：学号/姓名关键词搜索；可切换「按报名时间」或「按候补序号」排序
（候补按序号从小到大，便于确认谁排在最前面）。

**单条审核**：

| 当前状态 | 可执行 |
|---|---|
| 待审核 | 通过 / 驳回 |
| 候补 | 递补 / 驳回 |
| 已通过 | 驳回 |
| 已驳回 / 已取消 | 不可操作（申请人在用户端重新报名） |

- **通过**：生成电子票码。**名额已满时会拒绝通过**（提示 `名额已满（x/y）`），不会超卖。
- **驳回**：必须填写理由（前端必填、后端二次校验），理由会同步给申请人。
- **递补**：把候补转正，生成电子票码。名额已满时拒绝递补。
- 点击「详情」打开抽屉，查看学号、学院、报名/审核时间、审核人、电子票码、驳回理由。

**批量审核**：勾选表格左侧复选框后，点「批量通过」或「批量驳回（N）」；
批量驳回同样需要填写理由。逐条处理，状态冲突的记录（如已取消）会被跳过，
完成后提示成功条数与跳过条数。

**名额释放与候补自动转正**：驳回一个已通过报名时，名额立即释放，
系统会按候补序号自动把**最早的一名候补**转正。因此候补人数不会凭空减少后不再补位。

**导出 Excel**：右上角「导出 Excel」导出**当前筛选条件下**的全部报名，
列包含学号、姓名、学院、状态、候补序号、报名时间、审核时间、审核人、电子票码、驳回理由。
文件名带活动名与时间戳，例如 `数据库原理工作坊_报名名单_20260922153000.xls`。

### 4.4 签到管理 `/checkin`

仅**已发布**活动可选。页面分三块 + 底部记录表。

**① 动态签到码**：进入页面自动生成活动签到二维码，有效期 60 秒，
底部显示剩余秒数倒计时，**到点前 8 秒自动换新码**（也可手动点「立即刷新」）。
二维码下方显示签到窗口（活动起止时间）。

用途：管理员用大屏/手机展示此码，或把截图发到群里；成员端扫码后系统校验票码。

**② 扫码 / 手工签到**：

- 扫码模式：现场用相机扫成员电子票二维码，票码自动填入输入框后回车。
- 手工模式：直接输入票码（形如 `TK-1001-U0123-0435`）后回车。

**③ 手动补签**：用于成员手机没电、票码截图丢失等场景。
下拉框只列出「已通过审核且未签到」的成员（可搜索姓名），选择后点「确认手动补签」。
补签记录操作人，与扫码签到同等计入签到率。

**④ 实时签到看板**：右侧展示已批准人数、已签到人数、签到率进度条与最新签到名单，
**每 5 秒自动轮询刷新**，无需手动操作。

**签到校验规则**（后端强制执行，前端只负责展示错误信息）：

| 校验 | 失败提示 |
|---|---|
| 票码必须存在且属于该活动 | 票码无效，未找到对应报名 |
| 报名必须为「已通过」 | 该报名未通过审核，不可签到 |
| 必须在活动开始前 30 分钟 ~ 结束后 30 分钟内 | 签到尚未开始 / 签到已结束 |
| 同一报名只能签到一次 | 该同学已签到，请勿重复签到 |

**签到记录**：底部表格按时间倒序分页展示，含签到时间、学号、姓名、签到方式
（扫码签到 / 手动补签 / 定位签到）、补签操作人、签到 ID。

### 4.5 数据统计 `/statistics`

- **报名人数对比**：多活动分组柱状图，对比报名人数 / 通过数 / 已签到数。
- **签到率对比**：柱状图带 80% 目标线，低于目标显示橙色、达标显示绿色。
- **活动统计明细**：名额、报名、通过、驳回、候补、取消、已签到、签到率，含合计/平均汇总行。
- **看板口径**：累计报名、累计通过、整体签到率三个汇总指标。
- **导出 Excel**：导出全部活动统计明细。

**统计口径**：

- 报名人数 = 该活动全部报名记录数（含候补、已驳回、已取消）。
- 签到率 = 已签到 ÷ 通过人数（分母不含候补与驳回）。

## 五、常见问题

**Q：登录提示「登录态已失效，请重新登录」？**
令牌过期或被清理。返回登录页重新登录即可；真实后端模式下 401 会自动清除本地令牌并跳转登录页。

**Q：导出 Excel 打开后中文乱码？**
前端导出的文件带 UTF-8 BOM，Excel / WPS 均可正常打开。若仍乱码，请用 Excel 的「数据 → 从文本/CSV」导入并选择 UTF-8 编码。

**Q：为什么已发布活动改不了名额？**
发布态活动的名额、分类、时间被锁定，这是为了避免活动期间名额变更导致的超卖与不公平。
请先「下架」→「编辑」→再「发布」。

**Q：为什么驳回了一个人已通过报名，候补队列人数自动少了一个？**
名额释放后系统按候补序号自动把最早的候补转正，这是设计行为，不是数据丢失。

**Q：签到看板数字不动？**
看板每 5 秒轮询一次。若活动不在签到窗口内（开始前 30 分钟 ~ 结束后 30 分钟），
新签到请求会被后端拒绝，看板自然不再变化。

**Q：演示数据被我改乱了，想还原？**
点顶栏「重置演示数据」，或清除浏览器该站点 localStorage（键 `clubcue-admin-mock-db-v1`）。

## 六、与后端联调

前端默认可独立运行。后端接口就绪后：

1. 在 `client/.env` 中设置 `VITE_USE_MOCK=false`。
2. 若后端不在 `http://localhost:3001`，设置 `VITE_API_BASE_URL=https://实际地址/api/v1`；
   否则留空走 `vite.config.ts` 的 `/api` 代理。
3. 重启 `npm run dev`。

页面代码无需任何改动，接口路径与字段契约见 [管理端接口契约](./管理端接口契约.md)。
